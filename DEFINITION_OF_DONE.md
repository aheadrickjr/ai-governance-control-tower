# Definition of Done

## Project

AI Governance Control Tower

## Sprint Context

This Definition of Done supports the certification-to-portfolio sprint for:

- AWS AI Practitioner / AIF-C01
- AIGP / AI Governance Professional
- AI data governance portfolio development
- Globe & Anchor Digital Media Solutions service positioning

The goal is to ensure the project produces usable artifacts, not just study notes.

---

## Definition of Done Statement

The project is considered done when it contains a coherent, GitHub-ready AI governance package that demonstrates how an organization can intake, evaluate, approve, monitor, and control an AI-enabled use case.

The finished project must be understandable to:

- A hiring manager
- A recruiter
- A consulting prospect
- A technical reviewer
- A governance/risk stakeholder
- The project owner returning to the work later

---

## Day 1 Definition of Done

Day 1 is complete when the foundation files exist and are internally consistent.

Required Day 1 files:

- `README.md`
- `PROJECT_STORY.md`
- `DEFINITION_OF_DONE.md`
- `SPRINT_CHARTER.md`

Required Day 1 outcomes:

- Project purpose is clear
- First use case is selected
- Repository structure is defined
- Sprint goals are documented
- Success criteria are defined
- Build direction is clear for Day 2
- Files are saved in the OneDrive project folder
- Folder is ready to be committed to GitHub

---

## Sprint Definition of Done

The sprint is complete when the repository includes the following:

### 1. Foundation Documents

- `README.md`
- `PROJECT_STORY.md`
- `DEFINITION_OF_DONE.md`
- `SPRINT_CHARTER.md`

Each foundation document must clearly explain the project from a different angle:

- README: public-facing project overview
- PROJECT_STORY: narrative and purpose
- DEFINITION_OF_DONE: completion criteria
- SPRINT_CHARTER: execution plan

---

### 2. Governance Artifacts

The `docs/` folder must include:

- `ai-use-case-intake.md`
- `stakeholder-raci.md`
- `risk-impact-assessment.md`
- `control-checklist.md`
- `monitoring-escalation-model.md`
- `aws-ai-service-map.md`

Each artifact must be practical enough to reuse in a real governance review.

---

### 3. Templates

The `templates/` folder must include:

- `intake-form-template.md`
- `impact-assessment-template.md`
- `control-register-template.csv`
- `decision-log-template.md`

Templates must be reusable and not locked to only one sample use case.

---

### 4. Example Use Case

The `examples/` folder must include:

- `sample-ai-use-case-review.md`

The sample must demonstrate how the governance process works using one realistic AI use case.

The example must include:

- Business problem
- AI system purpose
- Stakeholders
- Data involved
- AWS AI/cloud services involved
- Risks
- Controls
- Approval path
- Monitoring requirements
- Escalation process

---

### 5. AWS AI Service Mapping

The project must show practical AWS AI service awareness.

The AWS service mapping must identify:

- Candidate AWS AI services
- What each service is used for
- Why the service may or may not fit the use case
- Governance considerations
- Security/privacy considerations
- Cost or operational concerns where relevant

---

### 6. AIGP Governance Alignment

The project must show practical AI governance understanding.

The governance model must include:

- Business purpose
- Stakeholders
- Roles and responsibilities
- Risk and impact assessment
- Human oversight
- Documentation requirements
- Monitoring
- Escalation
- Accountability

---

### 7. GitHub Readiness

The repository is GitHub-ready when:

- File names are clear
- Folder structure is clean
- Markdown renders correctly
- No local-only paths are required
- No private credentials are included
- No sensitive personal data is included
- The project can be understood from the README
- The repo tells a coherent story

---

## Quality Bar

The project does not need to be a fully automated application to be considered done.

It must be:

- Clear
- Practical
- Coherent
- Demonstrable
- Professionally useful
- Aligned to AI governance
- Aligned to AWS AI learning
- Suitable for interview or consulting discussion

---

## Not Done If

The project is not done if:

- It is only a folder structure
- It only contains study notes
- The first use case is unclear
- Governance artifacts are vague
- Risk controls are not documented
- AWS AI services are not mapped
- There is no sample use case
- The README does not explain the project
- The repo cannot be explained in a 3-minute conversation

---

## Final Demo Criteria

The project is demo-ready when the owner can explain:

1. The problem
2. The target user
3. The first AI use case
4. The governance intake process
5. The risk and impact assessment process
6. The AWS AI service mapping
7. The control model
8. The monitoring and escalation model
9. The value to a company
10. The value to a hiring manager or consulting prospect

I am not building this project to chase perfection.

The project is complete when it creates enough structured proof to support:

- Certification learning
- Portfolio credibility
- Consulting conversations
- Job search positioning
- Continued AI governance buildout
